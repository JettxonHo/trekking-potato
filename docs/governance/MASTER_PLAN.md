## 1. 产品目标

将徒步薯从“能够生成建议的 AI 小程序”升级为：

> 基于可信路线数据、明确时间窗口、确定性安全规则和清晰交互的徒步行前可行性检查工具；AI 只负责解释、补充和整理，不负责决定关键安全事实。

当前主产品形态继续采用微信小程序。H5 分享与作品集体验可作为后续补充；在核心正确性和真实用户验证完成前，不优先开发原生 App、多语言、大规模社区或商业化。

## 2. 不可违反的产品原则

### 2.1 正确性优先

实施顺序：

1. 数据单位与日期正确性
2. 路线识别与路线类型正确性
3. 安全规则确定性
4. 异常、降级和恢复完整性
5. 核心交互效率
6. 视觉与品牌表达
7. 新功能扩张

### 2.2 AI 的边界

下列事实必须由可信 API、确定性规则或验证过的路线数据决定：

- 天气数值、日期和单位
- 出发日期与行程时间窗口
- 路线身份、类型和海拔语义
- 是否属于技术攀登
- 高反、失温、雷暴、滑坠等基础风险触发条件
- 与上述风险对应的最低装备要求

LLM 只负责：解释、归纳、语言组织、非关键补充，以及明确表达不确定性。

### 2.3 单任务闭环

每轮只允许一个主要目标，必须经过：调查或复现 → 主控授权 → 最小实现 → 测试证据 → 主控审查 → 通过或返工。

## 3. 当前已识别的优先问题

### P0-1 风速单位正确性

当前天气请求未显式指定 `wind_speed_unit=ms`，但数据字段和界面按 `m/s` 解释。必须统一 API 请求、返回契约、Prompt 和 UI 单位，并补契约测试。

### P0-2 天气窗口与行程日期

天气必须从用户出发日期开始，并严格对应行程天数。超出预报范围时不得展示当前预报冒充行程天气，应返回明确的 `out_of_range` 状态。

### P0-3 路线类型贯穿

`climb / trek / tour` 等路线类型必须从路线库贯穿地理解析、规则引擎、建议生成和结果展示，禁止攀登路线静默退化为普通徒步。

### P0-4 模糊匹配确认闭环

后端返回 `needsConfirm` 时，前端必须进入确认状态，用户明确确认路线后才能查询天气和生成建议。

### P0-5 路线数据模型纠偏

“一个名称 + 一个坐标 + 山峰最高海拔”不能代表整条徒步路线。后续应区分 `place`、`route` 和 `routeVariant`，并逐步补充起终点、距离、爬升、路线最高点、典型天数和天气采样点。

### P0-6 确定性安全合并

规则引擎生成的最低安全装备和基础风险必须进入最终结果；LLM 不得通过遗漏或空数组覆盖确定性安全项。

### P1-1 第二阶段可信上下文

两阶段请求不应让客户端回传并决定可信天气与规则数据。目标方案为服务端保存短期上下文并返回 `queryId`，第二阶段仅凭 `queryId` 获取可信数据。

### P1-2 UGC 路线信任机制

手动坐标不能在查询成功前静默写入公共路线库。贡献必须用户知情、主动确认，并进入待验证状态。

### P1-3 前端状态和模块拆分

输入、路线确认、基础加载、建议加载、成功、降级、错误应使用显式状态模型。逐步拆分大型单页 Class Component 和云函数调用逻辑。

### P1-4 工程门禁

建立统一的 `test`、`lint`、`typecheck`、`build` 命令和 GitHub Actions；补充天气契约、完整编排、确认流程、Schema 和 UGC 测试。

## 4. 阶段路线图

### Phase A — 治理与基线

- 固化 Agent 入口、主控规划、执行协议和当前任务
- 记录基线测试与文档漂移
- 确保主控与执行 Agent 通过版本和哈希握手

### Phase B — P0 正确性修复

按顺序处理：风速单位 → 日期窗口 → 路线类型 → 确认流程 → 安全合并 → 第二阶段可信上下文 → UGC 时序与授权。

除主控明确调整外，不并行实施多个 P0 项。

### Phase C — 路线模型升级

建立路线变体模型，修复环线使用山峰海拔的问题；支持多天气采样点和可追溯来源。GPX 可用于行前分析，但不扩展为行中导航。

### Phase D — 核心体验提升

- 顶部输出“建议出发 / 谨慎出发 / 暂不建议”及依据
- 引入小时级天气与出发时间
- 装备清单改为可勾选 Checklist
- 搜索结果展示地区、路线变体、类型和典型天数
- 数据来源、更新时间和置信度可见

### Phase E — 验证与传播

- 真实用户测试和反馈闭环
- H5 结果分享或作品集 Demo
- README 补截图、演示、架构和验证数据
- 根据复用率和反馈决定是否扩展平台或原生端

## 5. 暂不执行

在 Phase B 未完成且没有真实用户信号前，暂不优先：

- iOS / Android 原生壳
- 多语言
- 社交信息流和评论社区
- 大规模社区评分
- 付费订阅
- 泛化的“去哪玩”推荐平台
- 仅为展示而进行的大规模视觉重构
