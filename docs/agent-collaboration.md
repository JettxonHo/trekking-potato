# 多 Agent 协作规范

- Version: `1.1.0`
- Governance: `TP-GOV-2.0.0`

## 1. 角色与权限

### Sol XHigh

负责仓库审计、产品和架构决策、Goal/Issue 拆分、任务合同、调度、复杂根因、独立 Review、合并判断、上下文检查点和最终验收。普通边界清楚的实现不由 Sol 主动承担。

Sol 仅在执行 Agent两轮返工仍失败、跨模块架构阻塞、复杂根因、紧急 Goal 阻塞或验证原型无法再拆分时直接修改业务代码，并必须记录原因。

### `luna-worker`

`luna-worker` 是边界明确实现任务的准确自定义 Agent 名称；其配置文件为
`~/.codex/agents/luna-worker.toml`，模型为 `gpt-5.6-luna`，推理强度为 `max`，逻辑角色为
`IMPLEMENTER`。创建时必须选择该自定义 Agent，不得以“Luna Max”逻辑角色或仅模型字符串代替。
实现 Agent读取合同、检查已有成果、实现、测试、自检、提交和返工。不得扩大范围、改变架构/公共
协议/依赖策略、进行迁移或降低验收，也不得批准或合并自身 PR。

Terra 的既有提交、PR、测试和审计证据继续有效，但不再是自动实现回退。未经人工再次明确授权，
Sol 不得创建新的 Terra 实现 Agent。若 `luna-worker` 不可发现或无法启动，停止新实现并记录
`STATUS: BLOCKED_LUNA_WORKER_UNAVAILABLE`。

## 2. 下发上下文包

Sol 只下发完成当前任务所需信息：Issue、合同、必读文档、涉及模块、固定决策、验收、测试、分支/基线、风险和禁止范围。完整聊天记录不是任务合同。

## 3. 返回结果包

执行 Agent返回：完成情况、修改摘要、实际文件、命令与退出码、计划差异、自主实现细节、已知限制、PR、建议重点 Review 位置和最终工作区状态。

## 4. Review 与返工

Sol 阅读实际 diff 和测试，不依赖 PR 自述。`CHANGES_REQUESTED` 必须指出文件、行为、严重度和期望；原执行 Agent修复并重新运行验证。不能因为执行 Agent声称已修复而跳过复审。

## 5. 并发

默认串行。并发前 Sol 检查文件、Schema、公共接口、数据库和依赖重叠，记录 Agent、Issue、分支、allowlist、契约、合并顺序和冲突责任人。当前共享工作区不能安全并行分支；只有提供隔离 worktree 后才可并行。并发收益低于冲突风险时保持串行。

## 6. 冲突处理

- 文档冲突：Sol 按权威层级修正文档后再继续。
- 代码与合同冲突：执行 Agent停止受影响文件并提供证据。
- 并发冲突：Sol 决定合并顺序；执行 Agent不得自行覆盖另一分支。
- 用户改动：保留并隔离；无法隔离时请求人工决定。

## 7. 人工确认

部署、生产配置、敏感数据、TP-D008 未授权的权限/隐私边界变化、不可逆迁移、重大技术栈替换、明显费用、Goal 外产品取舍和无法确定的真实需求必须人工确认。I19 的非破坏性私人历史收敛和公共 UGC 路径停用已经授权。

## 8. 失败回退

1. 首轮失败：同一执行 Agent按具体 Review 修复。
2. 第二轮失败：Sol 暂停局部修补，重新定位根因或拆分任务。
3. 架构或合同错误：Sol 修订决策和合同，旧 PR 保持未合并或关闭。
4. `luna-worker` 不可用：不得自动回退 Terra；记录配置检查、可见 Agent、交接状态和需要的人工操作。
5. 无法安全继续：标记 BLOCKED，更新 current-status，继续完全独立的任务。

## 9. 上下文检查点

里程碑、相关 Issue 批次、重大决策、阶段转换、Review 前或交接时更新 `docs/current-status.md` 和必要决策。恢复时按 `AGENTS.md` 顺序重新读取，不以模型摘要替代仓库事实。
